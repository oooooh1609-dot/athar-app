# الهيكلة الكاملة وخارطة الطريق — أثر (Athar)

هذا المستند يجيب سؤالين: **ما الشكل النهائي للتطبيق؟** و**كيف نصل إليه من حيث نحن الآن؟**

---

## 1. قرار معماري يجب حسمه أولًا

وثيقة المواصفات تطلب React Native + Expo. الموجود تطبيق ويب (TanStack Start + React 19). **التوصية: لا تُعِد الكتابة.**

الأسباب ملموسة لا نظرية:

|                       | إعادة الكتابة إلى React Native                                                                                | البقاء على الويب + PWA             |
| --------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| ما يُفقد              | محرّك تحسين الصور، نظام قراءة النقوش، لوحات مفاتيح الخطوط القديمة، نظام الملحقات المعزول، بنية Supabase كاملة | لا شيء                             |
| معالجة البكسل         | يجب إعادة كتابتها بـNative modules؛ JS في RN بطيء جدًا لـCLAHE على صورة 24 ميجابكسل                           | تعمل الآن عبر Canvas + Web Workers |
| الملحقات (extensions) | عزل الكود المستورد في RN مشكلة غير محلولة عمليًا                                                              | محلولة عبر Web Worker              |
| التوزيع               | مراجعة App Store لكل تحديث                                                                                    | نشر فوري                           |
| الوصول الميداني       | تثبيت مسبق مطلوب                                                                                              | رابط يعمل، ويُثبَّت كتطبيق         |
| ما يُكسب فعلًا        | AR حقيقي (ARKit/ARCore)، وصول أعمق للكاميرا                                                                   | —                                  |

الشيء الوحيد الذي يستحق Native هو **AR**. والقسم 4 يشرح لماذا AR ليس ما تحتاجه أصلًا لتوثيق النقوش.

**المسار الموصى به:** ويب + PWA الآن، وإن ثبتت الحاجة لـAR لاحقًا فتطبيق مرافق صغير يتكامل مع نفس الـAPI — لا إعادة كتابة.

## 3. ما أُضيف في هذه الدفعة

### 3.1 محرّك القياس — `src/lib/measure.ts`

الطريقة ليست AR بل ما يُستخدم فعليًا في التنقيب: ضع جسمًا معلوم الطول في الإطار، وقِس كل شيء بالنسبة إليه.

ما يميّزه عن قياس ساذج:

- **انتشار الخطأ.** كل نتيجة تحمل عدم يقين محسوبًا من دقة وضع المرجع. مرجع طوله ٥٠٠ بكسل ينتج ±٠٫٦٪؛ عملة معدنية طولها ٤٠ بكسل تنتج **±٧٫١٪** — والتطبيق يقول ذلك صراحةً بدل أن يعرض رقمًا واثقًا بلا أساس.
- **المساحة تضاعف الخطأ النسبي** (لأنها تتناسب مع مربع المقياس) — مطبَّق.
- **رفض العمل بلا مرجع.** `evaluate()` تُعيد `null` بدل عدد بكسلات متنكّر في هيئة مليمترات.
- **تحذير صريح عن حدود الطريقة**: تصلح لسطح مستوٍ صُوِّر عموديًا فقط. الارتفاع لا يُستخرج من صورة واحدة، والتطبيق لا يدّعي ذلك.

**تم التحقق:** ٢٣ فحصًا حسابيًا نُفِّذت فعليًا (مثلث ٣-٤-٥، صيغة الحذاء بالاتجاهين، شكل مقعّر على هيئة L، عتبات الوحدات، المدخلات المنحلّة) — جميعها نجحت.

### 3.2 الموقع — `src/lib/geo.ts`

`navigator.geolocation` مباشرة، بلا أي SDK خرائط وبلا مزوّد بلاطات. **هذا قرار مقصود:** إحداثيات موقع أثري غير منشور معلومة حسّاسة، وإرسالها تلقائيًا إلى خدمة خرائط طرف ثالث خيار افتراضي خاطئ لتطبيق كهذا. الخريطة تُفتح فقط حين ينقر المستخدم.

**تم التحقق:** ٧ فحوص (تحويل DMS في نصفي الكرة، مسافة الدائرة العظمى مقابل قيم مرجعية معروفة: درجة عرض واحدة = ١١١٫٢ كم، خطوة ١١ مترًا، النقطة المقابلة).

### 3.3 التقرير — `src/lib/report.ts`

PDF عبر مسار الطباعة في المتصفح، **بلا أي مكتبة PDF**. السببان:

1. مكتبات PDF في JS تضيف ~٣٠٠ كيلوبايت قبل الخطوط، على تطبيق يُحمَّل عبر اتصالات ميدانية.
2. تشكيل الحروف العربية واتجاه RTL يُخطئان كثيرًا في هذه المكتبات؛ محرّك النصوص في المتصفح يعطيهما مجانًا وبشكل صحيح.

الثمن: يمرّ المستخدم بنافذة طباعة بدل تنزيل مباشر. إن صار هذا غير مقبول، `buildReportHtml` هي نقطة الاستبدال الوحيدة.

التقرير يتضمّن تنويهًا ثابتًا بأن القراءة اقتراح آلي غير مُراجَع، وأن ألوان الصورة المعالَجة ألوان زائفة.

### 3.4 وحدات مساندة

- `object-url.ts` — خطّاف `useObjectUrl` و`downloadBlob`، يُنهيان تسريبات الذاكرة الموصوفة في `AUDIT.md`.
- `doc-dict.ts` — ٥٨ مفتاحًا × ٤ لغات. **تم التحقق آليًا** من تطابق مجموعات المفاتيح في اللغات الأربع تمامًا.
- `athar-db.ts` — النسخة ٤: حقلا `location` و`measurements` اختياريان، فالسجلات القديمة تبقى مقروءة كما هي.

## 4. المراحل المتبقية

### المرحلة ٢ — PWA والعمل دون اتصال ✅ أُنجزت (عدا الطابور)

- ✅ `manifest.webmanifest` + مجموعة أيقونات كاملة (١٩٢، ٥١٢، maskable، وأيقونة iOS المنفصلة لأن iOS يتجاهل بيان التثبيت).
- ✅ عامل خدمة `public/sw.js` بقواعد صريحة، **٢٠ فحصًا نُفِّذت على الكود المنشور نفسه**:
  - صفحات HTML: الشبكة أولًا دائمًا. تطبيق SSR يقدّم صدفة قديمة يحبس المستخدم على إصدار سابق بلا مخرج.
  - `/api/` لا يُخزَّن إطلاقًا. قراءة قديمة أو حالة مهمة قديمة أو فحص صلاحية قديم أسوأ من فشل صريح.
  - أصول البناء (أسماؤها مجزّأة بالمحتوى): الذاكرة أولًا مع تحديث في الخلفية — آمن لأن تغيّر الملف يعني تغيّر الرابط.
  - الخطوط من Google: مخزَّنة، وإلا فقد التطبيق حروفه العربية دون اتصال.
  - طلبات Range تمرّ كما هي، وإلا تعطّل التنقّل داخل الفيديو.
- ✅ **لا يستولي إصدار جديد على الجلسة تلقائيًا.** ينتظر حتى يضغط المستخدم «تحديث»، فلا يُبدَّل البناء تحت شخص في منتصف تحرير صورة.
- ✅ لا يُسجَّل عامل الخدمة إلا على HTTPS وخارج معاينة Lovable. عامل خدمة عالق يواصل تقديم بناء قديم بعد حذف ملفه، وهذا أسوأ عطل يمكن شحنه.
- ✅ مخرج طوارئ: `unregisterAll()` في `src/lib/pwa.ts`.
- ✅ شريط حالة يوضّح **ما الذي ما زال يعمل** دون اتصال، لا مجرد إعلان العطل.
- ✅ **الطابور الصادر أُنجز** (`src/lib/outbox.ts`) — مهام إعادة البناء تُصطفّ دون اتصال وتُرسَل عند عودة الشبكة، بتراجع أسّي ٣٠ث→٥د بسقف (بلا سقف، المحاولة الثانية عشرة تقع بعد ١٧ ساعة).
  - **قراءة النقوش لا تُصطفّ عمدًا.** القراءة شيء ينظر إليه المُسجِّل الآن ويتصرّف بناءً عليه؛ تسليمها بصمت بعد ثلاث ساعات بلا نظام إشعارات ولا شاشة تستقبلها أسوأ من فشل صريح لحظة الطلب.

### المرحلة ٣ — التصوير البانورامي ٣٦٠° ✅ أُنجز المسار (أ)

**ما بُني:** عارض ٣٦٠° كامل (`src/lib/panorama.ts` + `PanoramaViewer.tsx`) بلا أي مكتبة — لا three.js ولا WebGL. الإسقاط بأخذ عيّنات على Canvas: three.js أسرع، لكنه ~٦٠٠ كيلوبايت قبل تحميل أول بانوراما، على تطبيق غايته العمل على اتصال ميداني.

يدعم: السحب للنظر، والتقريب باللمس أو العجلة، ووضع نقاط معلومات على الجدران، وحارس نسبة أبعاد يحذّر إذا لم تكن الصورة ٢:١.

**٣٤ فحصًا نُفِّذت**، منها رحلة ذهاب وإياب بين إحداثيات الشاشة واتجاهات الكرة، وفحص أن ٢٢٥ عيّنة من زوايا مختلفة تقع كلها داخل حدود الصورة.

**ما لم يُبنَ ولن يُبنى: التجميع (stitching).** دمج صور متداخلة في صورة equirectangular يحتاج كشف خصائص وتقدير homography ومزجًا متعدد النطاقات — مشروع قائم بذاته، وتطبيق الكاميرا في هاتفك يؤدّيه جيدًا بالفعل. العارض يأخذ البانوراما الجاهزة.

#### المرحلة ٣ — التصوير البانورامي ٣٦٠°

هنا يجب الوضوح: **التجميع (stitching) الحقيقي في المتصفح مشروع بحدّ ذاته** — كشف خصائص، مطابقة، تقدير homography بـRANSAC، مزج متعدد النطاقات. ليس ميزة تُضاف في جلسة.

مساران واقعيان:

- **(أ) عارض فقط:** يرفع المستخدم صورة equirectangular جاهزة (من كاميرا ٣٦٠° أو تطبيق الهاتف)، والتطبيق يعرضها ويسمح بوضع نقاط معلومات مرتبطة بنقوش. يحتاج Three.js. جهد قليل، قيمة عالية.
- **(ب) تجميع من جهة الخادم:** إضافة Hugin إلى عامل Meshroom القائم — البنية موجودة فعلًا (طابور مهام + استقصاء + تخزين). جهد متوسط، والنتيجة أعلى جودة بكثير من أي تجميع في المتصفح.

**التوصية: (أ) ثم (ب).** لا تحاول التجميع في المتصفح.

</details>

### المرحلة ٤ — الخرائط وتجميع المواقع ✅ أُنجزت (بلا بلاطات)

- ✅ تجميع المشاريع القريبة في «مواقع» (`src/lib/sites.ts`) بعنقدة أحادية الرابط نصف قطرها ٥٠ م. **أحادية الرابط قصدًا:** الموقع يُمشى على امتداد وادٍ أو واجهة صخرية، فتتشكّل السجلات كسلسلة لا ككتلة، والعنقدة حول المركز كانت ستقسّم جدارًا واحدًا إلى ثلاثة مواقع.
- ✅ تصدير GeoJSON (RFC 7946) وCSV — هذا ما يطلبه الباحثون فعليًا للاستيراد في QGIS. دقة التحديد تُصدَّر مع كل نقطة: موضع بلا نصف قطر خطئه يُعامَل كأدقّ مما هو.
- ❌ **لا بلاطات خرائط، عمدًا.** رسم خريطة تفاعلية يعني طلب بلاطات لإحداثيات كل موقع اكتشاف من طرف ثالث — إفصاح لم يوافق عليه المُسجِّل عن مواقع غير منشورة. الملف الذي يفتحه الباحث في QGIS يؤدي الغرض بلا هذا الثمن.

### المرحلة ٥ — المزامنة بين الأجهزة

الأصعب، وأُخّر عمدًا. المشاريع الآن محلية بالكامل، وهذا اختيار جيد للخصوصية. المزامنة تعني:

- رفع الصور إلى Supabase Storage مع RLS لكل مالك.
- حلّ تعارضات التحرير (آخر كتابة تفوز لا يكفي لتصويبات القراءة).
- تشفير من طرف إلى طرف للإحداثيات — وإلا صار خادمك قاعدة بيانات لمواقع أثرية غير منشورة، وهي مسؤولية لا تريدها.

## 5. الترتيب المقترح

1. **أصلح الأمن أولًا** — القسم ٧ من `AUDIT.md`. لا معنى لبناء ميزات فوق نظام مصادقة مكسور.
2. `npm run build` وتحقّق من الوحدات المضافة في هذه الدفعة.
3. ~~المرحلة ٢ (PWA)~~ — أُنجزت، عدا الطابور الصادر. أكمله أولًا.
4. المرحلة ٤ (الخرائط) — تستفيد مباشرة من `geo.ts` الجاهز.
5. المرحلة ٣(أ) (عارض ٣٦٠°).
6. المرحلة ٥ (المزامنة) — بعد أن تستقرّ البقية.

## 6. تحذير صريح عن حالة هذه الدفعة

المنطق الحسابي في `measure.ts` و`geo.ts` **مُختبَر فعليًا** (٣٠ فحصًا نُفِّذت ونجحت)، وتطابق مفاتيح اللغات **مُتحقَّق منه آليًا**.

أما `MeasureCanvas.tsx` و`FieldRecord.tsx` و`report.ts` فمراجَعة يدويًا فقط — لا مُصرِّف TypeScript ولا تشغيل للمتصفح في البيئة التي كُتبت فيها. توقّع أخطاء تصريف صغيرة (أنواع، استيرادات) عند أول `npm run build`. المنطق سليم؛ ما يحتاج تحقّقًا هو الالتصاق بين الأجزاء.

**تم الوصل:** `MeasureCanvas` صار موصولًا داخل `Workspace.tsx` بعد كتلة المعاينة — يعمل على الصورة المحسَّنة، وتُحفظ القياسات مع المشروع. و`ConnectionBar` موصول تحت ترويسة `index.tsx`.

**ما زال بلا تحقّق:** `MeasureCanvas.tsx` و`FieldRecord.tsx` و`ConnectionBar.tsx` و`report.ts` — مراجَعة يدويًا فقط. المنطق الخالص في `measure.ts` و`geo.ts` و`sw.js` مُختبَر فعليًا (٥٠ فحصًا)، لكن التصريف والتشغيل في المتصفح لم يحدثا.

## 7. كيف تختبر العمل دون اتصال

عامل الخدمة لا يُسجَّل إلا على HTTPS، فلن يعمل في `npm run dev`. الاختبار الصحيح:

```bash
npm run build && npm run preview
```

ثم في أدوات المطوّر:

1. **Application → Service Workers** — تأكّد أن `sw.js` مُفعَّل (activated).
2. **Application → Manifest** — يجب أن يظهر زرّ التثبيت بلا تحذيرات.
3. **Network → Offline** ثم أعد التحميل — تظهر الصدفة من الذاكرة، ويظهر شريط «لا يوجد اتصال».
4. جرّب تحسين صورة وقياسها وحفظها **وأنت دون اتصال** — يجب أن تنجح كلها.
5. جرّب قراءة نقش دون اتصال — يجب أن تفشل بوضوح لا أن تُرجع نتيجة قديمة.

**اختبار التحديث:** انشر بناءً جديدًا وأعد التحميل. يجب أن يظهر شريط «تتوفر نسخة جديدة» ولا يحدث شيء حتى تضغطه.

**إن علق عامل خدمة معطوب**، من وحدة التحكم:

```js
import("/src/lib/pwa").then((m) => m.unregisterAll()).then(() => location.reload());
```

## 8. تشغيل الفحوص

الفحوص لا تحتاج تثبيت أي حزمة — Node وحده يكفي:

```bash
node docs/measure.test.mjs   # ٢٣ فحصًا لحسابات القياس
node docs/geo.test.mjs       # ٧ فحوص للإحداثيات والمسافات
node docs/sw.test.mjs        # ٢٠ فحصًا لقواعد التخزين، على sw.js نفسه
```

`sw.test.mjs` يستخرج `chooseStrategy` من `public/sw.js` الفعلي وينفّذها، فلا يختبر نسخة قد تتباعد عن المنشور.
